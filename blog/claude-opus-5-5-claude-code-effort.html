Claude Opus 5.5 で Claude Code はどう変わる？ — 何もしなければ effort は medium で動く

2026年9月22日（米国時間）に公開された Claude Code v2.1.280 で Claude Opus 5.5 が追加され、Pro と Team Standard の既定モデルが Sonnet から Opus（Opus 5.5）に変わりました1。日本時間では9月23日 1:38 の公開です。

同じモデルの話なのに、使った人の評価は驚くほど割れています。その差には、それぞれの設定や CLAUDE.md といった環境の違い（ハーネス）も効いているのだろうと私は思っています。

評価を寄せた人の中には、effort の設定そのものに気づいた人もいます。Hacker News のある利用者は、Opus 5.5 に現在のブランチのコードレビューを頼んだところ、示された5つの行番号のうち4つが間違っていたと書いています。続けて「Claude の CLI 画面の隅に “Effort: medium” と出ているのに気づいた。前に high にしていたはずなのに、いつ medium に戻ったのかわからない」とも書いています2。

effort とは、Claude がどれだけ考えるか（思考の深さ）を調整する設定で、Claude Code では low から max までの5段階から選びます3。平たく言えば「考える深さのつまみ」です。

この記事を読むと、自分の Opus 5.5 がいまどの effort で動いているかを確かめ、据え置くか変えるかを意図して選べるようになります。

Note

対象は Claude Code v2.1.280 以降と Claude Opus 5.5（claude-opus-5-5）です。事実は 2026年9月25日時点の公式ドキュメントに基づきます。

Opus 5 までの Claude Code の effort はどう決まっていたか

Opus 5 の既定の effort は high でした34。何も設定しなければ、Opus 5 は high で動いていました（Opus 5 を使っていた頃の記録はOpus 5 にブログを書かせた記事にまとめています）。

もう1つ押さえておきたいのが、effort の保存形式が途中で変わっていることです。

  • v2.1.251（2026年8月28日、米国時間）より前: /effort はユーザー設定の トップレベル に effortLevel を書いていました。全モデル共通の1つの値です15。
  • v2.1.251 以降: /effort は モデルごと に、modelSettings の下へ保存します15。

以前は全モデル共通のつまみが1つだけあり、いまはモデルごとにつまみがある、と考えるとわかりやすいと思います。

Opus 5 と Opus 5.5 の effort の違い：3つの変化

Opus 5.5 では、何も指定しないときの effort が1段階低い名前になり、古い形式の設定も効かなくなりました。ただし、同じ名前のレベルでも中身は同じではありません。

Opus 5Opus 5.5
何も指定しないときの efforthighmedium
ユーザー設定（~/.claude/settings.json）のトップレベル effortLevel効く効かない（プロジェクト・ローカル・管理設定と --settings の値は効く）
同じレベル名での思考量—Opus 5 より1ターンあたり多く考える傾向（とくに xhigh・max）

つまり、環境変数や起動オプションで effort を指定せず、プロジェクト設定などにも値が無ければ、Opus 5 のときの感覚で何も触らずに使うと medium で動きます。

なお Pro と Team Standard では、v2.1.280 から Claude Code の既定モデル自体も Sonnet 5 から Opus 5.5 に変わりました3。

既定の effort が medium になった

Claude Platform のドキュメントは、Opus 5 との挙動の違いとして次のように書いています6。

A request that omits effort runs at medium; on Claude Opus 5 it ran at high.

（effort を省略したリクエストは medium で動く。Claude Opus 5 では high で動いていた）

Claude Code のドキュメントも、各モデルの既定を次のように説明しています3。

high on every model that supports effort, except that Opus 5.5 defaults to medium, Opus 4.7 defaults to xhigh, …

（effort に対応するモデルでは high。ただし Opus 5.5 の既定は medium、Opus 4.7 の既定は xhigh で……）

settings.json のトップレベル effortLevel は Opus 5.5 に効かない

ユーザー設定のトップレベルに effortLevel を残していても、Opus 5.5 には効きません。Claude Code のドキュメントの説明は次のとおりです3。

a top-level effortLevel in your user settings file doesn’t count for Opus 5.5 … it keeps applying where it applied before, on Opus 5, Fable 5.1, and earlier models, while Opus 5.5 and models released after it start at their own default until you choose a level for them with /effort or the /model picker.

（ユーザー設定ファイルのトップレベルの effortLevel は Opus 5.5 には数えられない。〔中略〕Opus 5、Fable 5.1 とそれ以前のモデルにはこれまでどおり適用されるが、Opus 5.5 とそれ以降のモデルは、/effort か /model のピッカーでレベルを選ぶまで、それぞれの既定値から始まる）

効かないのは、ユーザー設定（~/.claude/settings.json）のトップレベルの値だけです。同じ段落は続けて “A top-level effortLevel in project, local, or managed settings, or one passed with --settings, applies to every model.” と書いています3。プロジェクト・ローカル・管理設定のトップレベルの値や、--settings で渡した値は Opus 5.5 にも効きます。

v2.1.280 の CHANGELOG にも、“Changed an effort level saved before /effort became per-model to no longer apply to newly released models such as Opus 5.5” とあります1。

同じレベル名でも中身は同じではない

名前が1段階下がったことを、公式は品質が1段階下がったこととは説明していません。Opus 5.5 のプロンプトガイドは、Anthropic のテストでは Opus 5.5 の medium が、コーディングと知識労働の評価で Opus 5 の high と同等以上だったと書いています7。

in Anthropic’s testing, Claude Opus 5.5 at medium matches or exceeds Claude Opus 5 at high on coding and knowledge-work evaluations

一方で、同じ Opus 5.5 の中で比べれば、medium は high より思考を減らすレベルです。Claude Code のレベル表は medium を “Reduces token usage for cost-sensitive work that can trade off some intelligence. The default on Opus 5.5” と説明しています3。「Opus 5 の high と比べてどうか」（モデル間）と「同じ Opus 5.5 の medium と high はどう違うか」（モデル内）は、別の軸の話です。

そもそも、レベル名が同じでもモデルが違えば中身は揃っていません3。

The effort scale is calibrated per model, so the same level name does not represent the same underlying value across models.

（effort の尺度はモデルごとに調整されているので、同じレベル名でもモデルが違えば同じ値を表さない）

さらに、同じレベルなら Opus 5.5 は Opus 5 より多く考える傾向があります。“At the same effort setting the model tends to think more per turn than Claude Opus 5, most of all at xhigh and max.” とされています6。その帰結として、プロンプトガイドは “If you keep the effort value you set for Claude Opus 5, expect longer turns and more output tokens.” と書いています7。Opus 5 で使っていた値をそのまま持ち込むと、ターンが長くなり出力トークンが増える、ということです。

私の Claude Code では、切り替えた瞬間に medium になっていた

自分の Claude Code のセッション記録（トランスクリプト）と設定ファイルを、Claude に集計させました。トランスクリプトには応答ごとに effort が記録されています（v2.1.212 の CHANGELOG に “Changed session transcripts to record the reasoning effort level on each assistant message” とあります1）。日時はすべて日本時間です。

Opus 5 の期間はすべて high だった。 2026年8月27日〜9月25日の直近25セッションのうち、Opus 5 を使った18本は、すべて effort が high でした。この期間、Opus に effort を保存した記録はなく、high は Opus 5 の既定値でした。25本の内訳は Opus 5 が18本、Sonnet 5 が4本、Opus 5.5 が4本です。9月23日の切り替えのセッション1本が Opus 5 と Opus 5.5 の両方に入るので、足すと26になります。

/model で切り替えた次の応答から medium になった。 9月23日 2:54 に /model で Opus 5.5 を選びました。そのときの出力は次の1行です。

Set model to `Opus 5.5 (default)` and saved as your default for new sessions

その次の応答から、effort は medium になりました。この間、effort の操作は一度もしていません。

その後もずっと medium のまま。 9月25日までの Opus 5.5 のセッション（切り替えのセッションの後半を含む4本）は、すべて medium のままでした。/effort は一度も実行していません。

設定ファイルには Sonnet 5 の effort だけがあった。 9月25日時点で ~/.claude/settings.json に保存されていたのは、Sonnet 5 の effort（high）だけでした。実物から effort に関係するキーだけを抜き出すと、次のとおりです。

{
  "modelSettings": {
    "claude-sonnet-5": {
      "effortLevel": "high"
    }
  }
}

Opus 5.5 の項目も、トップレベルの effortLevel もありません。

ここから読み取れることは3つです。

  • 私のケースは、旧設定が引き継がれなかった例ではありません。記録のある期間、Opus に effort を保存しておらず、既定値そのものが high から medium に変わった 例です。
  • 公式の解決順（明示の指定 → 保存した設定 → モデルの既定値）に照らすと3、保存が無い以上 medium になるのは仕様どおりで、記録と一致します。
  • 私は記録のある期間、Opus の effort を一度も選んでいなかったので、変化に気づく場面がありませんでした。モデルを選び直したときの出力にも、effort は出てきません（上の1行のとおりです）。

Claude Code で Opus 5.5 の effort を確認して選び直すやり方

ここからの操作結果は、公式ドキュメントの記述に基づきます。

1. いまの effort を確かめる

いちばん手早いのは、セッションのヘッダーを見ることです。effort はモデル名の隣に表示されます3。

The current effort level is also shown in the session header next to the model name, for example “with low effort”

/model を開かなくても、いまどのレベルで動いているかがわかります。

2. 設定ファイルを確かめる

次に ~/.claude/settings.json の modelSettings に claude-opus-5-5 の項目があるかを見ます。項目が無く、環境変数 CLAUDE_CODE_EFFORT_LEVEL・起動オプション --effort・プロジェクトなどの設定にも指定が無ければ、既定の medium で動きます3。

見落としやすい点が2つあります。

  • ユーザー設定のトップレベルに effortLevel があっても、Opus 5.5 には効きません（前述）。
  • modelSettings はモデルごとの保存なので、Opus 5 用に保存した値も Opus 5.5 には使われません。ドキュメントのとおり、Opus 5.5 は “start at their own default until you choose a level for them” です3。

3. 選び直す

保存はモデルごとなので、Opus 5.5 を選んだ状態で操作します3。操作ごとの効き方は次のとおりです3。

  • /effort を引数なしで実行 → スライダーが開きます。
  • /effort high のようにレベル名を付けて実行 → その値を既定として保存し、以後のセッションにも適用します。
  • スライダーか /model のピッカーで Enter → 既定として保存します。
  • スライダーか /model のピッカーで s → そのセッションだけに適用します（v2.1.257 以降）。
  • /effort auto → 使用中のモデルに保存したレベルを消します。
  • max → 環境変数 CLAUDE_CODE_EFFORT_LEVEL で指定しない限り、そのセッションだけに適用されます。

保存か一時適用かは、確定のしかたで決まります。Enter とレベル名の直接指定は保存、s はそのセッションだけです。

4. 公式の設定例

保存先の形を確かめたいときのために、Settings reference に載っている公式の例を示します。前置きは “This example keeps Opus 5.5 at high while other models use their own saved or default levels” です5。

{
  "modelSettings": {
    "claude-opus-5-5": {
      "effortLevel": "high"
    }
  }
}

保存先のキーはモデルの正式名（claude-opus-5-5）で、エイリアスや [1m] 付きの ID も同じ項目に対応します5。手で書くより、/effort を実行して Claude Code に書かせるほうが確実です。

5. 1回だけ深く考えさせたいとき

プロンプトのどこかに ultrathink と書きます。そのターンだけ深く考えるよう求める指示が加わります。セッションの effort も、API に送る effort も変わりません3。“think hard” などの言い回しはキーワードとして扱われず、普通のプロンプトの文として渡されます3。

Opus 5.5 の effort はどのレベルを選ぶべきか

公式の指針は「たいていのタスクはモデルの既定の effort を使う」です8。

Our guidance is that for most tasks you should use the model’s default effort level.

ただしこれは Opus 5.5 の登場前、2026年7月7日の公式ブログの記述です。

それでも、ここでいう「選び直す」は「high に上げる」という意味ではありません。既定が変わったことを知ったうえで、medium の据え置きも含めて、意図して選ぶということです。

選ぶときの材料になる公式の記述は次の3つです。

  • Opus 5 で使っていた値をそのまま持ち込むと、ターンが長くなり出力トークンが増えます7。
  • 思考を減らしたいときは、プロンプトで頼むより effort を下げるほうが確実です。“Lowering effort reduces thinking, and with it cost and latency, more reliably than prompt instructions do.” とされています7。
  • max は “may show diminishing returns and is prone to overthinking. Test before adopting broadly” とされています3。上げるほど良くなるとは限らず、広く使う前に試すように、ということです。

既定値は、提供者が品質とコストの釣り合いで選んだ値であって、自分の用途に合う保証はありません。モデルを切り替えたら、既定値の確認までを切り替え作業に含めたいと私は考えています。

なお、Claude Code 以外で API を直接呼んでいる場合も、effort を省略すれば medium で動きます6。

よくある質問（FAQ）

Q. Claude Code で Opus 5.5 の effort の既定値はいくつですか？

A. medium です。Opus 5 の既定は high だったので、1段階低い名前から始まります。いまの値はセッションのヘッダーに表示されます。

Q. settings.json の effortLevel が Opus 5.5 に効かないのはなぜですか？

A. ユーザー設定のトップレベルにある effortLevel は、/effort がモデルごとに保存するようになる前（v2.1.251 より前）の古い形式で、Opus 5.5 以降のモデルには適用されない仕様だからです。/effort か /model で Opus 5.5 用のレベルを選ぶと、modelSettings に保存されます。プロジェクト・ローカル・管理設定のトップレベルの値は、Opus 5.5 にも効きます。なお modelSettings はモデルごとの保存なので、Opus 5 用に保存した値も Opus 5.5 には使われません。

Q. Opus 5.5 の effort は medium と high のどちらにすべきですか？

A. まずは既定の medium で試すのが、公式の指針に沿った選び方です。Anthropic のテストでは、Opus 5.5 の medium はコーディングと知識労働の評価で Opus 5 の high と同等以上でした。より丁寧さが欲しい作業だけ high 以上に上げます。そのセッションの間だけ上げたいなら /effort のスライダーで s を、1回の応答だけ深く考えさせたいならプロンプトに ultrathink を使います（ultrathink は effort の値そのものは変えません）。

まとめ

  • Claude Code v2.1.280 で、Pro と Team Standard の既定モデルは Opus 5.5 になった。
  • Opus 5.5 の effort の既定は medium で、Opus 5 の既定 high より1段階低い名前から始まる。
  • ユーザー設定のトップレベルに残した旧形式の effortLevel は、Opus 5.5 には効かない（プロジェクト・ローカル・管理設定と --settings の値は効く）。
  • 私の Claude Code では、/model で Opus 5.5 を選んだ次の応答から medium になり、その後も（2026年9月25日まで）effort を一度も触らないまま medium で動いていた。
  • 同じレベル名でもモデルごとに中身は違う。公式の指針は「たいていは既定で」なので、上げるかどうかは作業に合わせて意図して選ぶ。
