Claude Codeの週次利用制限と付き合う配分術──「/usage」で可視化し、ヘビーなタスクを計画的に投入する

はじめに──週の後半、Claude Codeが止まる「あの瞬間」

大規模なリファクタリングに着手した木曜の午後、あるいは複数のサブエージェントを並行実行してタスクを一気に片付けようとした金曜の朝——そんなタイミングに限って、Claude Codeが週次利用制限に達して手が止まってしまった経験はないでしょうか。

コンテキスト消費の激しい開発タスクをこなすほど、週の後半に制限へ突き当たりやすくなるのは、Claude Codeをヘビーに使いこなしているエンジニアほど直面しやすい悩みです。本記事では、この「週の後半に息切れする」問題を、利用状況の可視化とタスクの配分計画によって解消する考え方を解説します。

/usage コマンドで自分の利用枠を可視化する

対策の第一歩は、感覚ではなく数字で残量を把握することです。Claude CodeのCLI上で次のコマンドを実行すると、現在の週次利用制限に対する消化状況や残量が表示されます。

/usage

このコマンドは、週の頭に一度実行して終わりにするのではなく、大きめのタスクに着手する前に毎回確認する習慣にすることで効果を発揮します。「月曜に見た時はまだ余裕があったはず」という思い込みで木曜にリファクタリングへ突入し、途中で制限に当たって作業を中断させられる——というのが最も避けたい事態だからです。

なお、5時間ごとに設定されている利用制限（5-hour limit）と週次の利用制限は別枠で管理されています。/usage の表示でどちらの制限に近づいているのかを混同しないよう注意してください。

タスクの重さで週内配分を決める

利用枠が可視化できたら、次はそれを週内にどう配分するかです。すべてのタスクを早い者勝ちで消化すると、結局「週の後半に息切れする」パターンに逆戻りします。おすすめは、タスクをあらかじめ次の3段階に分けて優先順位を決めておくことです。

  • 必須タスク（先に確保）: 納期のあるバグ修正やレビュー対応など、その週のうちに必ず終える必要がある作業。まず必要な枠を見積もり、/usage で残量が確保できているか確認してから着手する
  • 重量級タスク（余力を見て投入）: コンテキスト消費が大きい大規模リファクタリングや、複数のサブエージェントを使った並行調査・実装。週の前半、/usage の残量に余裕がある時間帯に前倒しで着手する
  • 反復検証タスク（隙間で回す）: TDDループでの小さな修正と再テストの往復など、1回あたりの消費は小さいが回数を重ねるタスク。残量を見ながら随時こなす

この配分を週の初めに決めておくだけで、「週の後半になって重いタスクに手を付けられない」という事態をかなり防げます。

記録：週次利用制限50%増量キャンペーン（2026年5月13日〜8月19日）

上記の配分術に加えて、Anthropicは期間限定で週次利用制限を引き上げるキャンペーンを実施していました。今後同様のキャンペーンが行われた際の参考として、当時の内容を記録しておきます。

Anthropicの公式サポート記事（Claude Code May–August 2026 weekly limits promotion）によると、実施期間は2026年5月13日から2026年8月19日まで、対象プランは Pro / Max / Team および レガシー形式の Enterprise 座席でした（Free プラン、消費ベースの Enterprise 座席は対象外）。5時間ごとの利用制限は増量の対象外です。

このようなキャンペーンが実施されている期間は、前述の「配分術」における重量級タスクの投入を積極化する好機になります。普段は週次制限を気にして後回しにしがちな大規模リファクタリングや技術的負債の一括解消を、このタイミングでまとめて片付けるという判断も有効です。

まとめ──可視化と配分で「気づいたら制限」を防ぐ

Claude Codeの週次利用制限に振り回されないためには、キャンペーンのような一時的な増量措置を待つのではなく、/usage による可視化と、タスクの重さに応じた週内配分をルーティン化しておくことが本質的な対策になります。増量キャンペーンが実施されている期間は、それを重量級タスクの投入タイミングとして活用するとよいでしょう。
