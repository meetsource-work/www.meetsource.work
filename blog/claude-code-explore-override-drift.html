Claude Code の組み込み Explore を Explore.md で上書きすると仕様変更が見えなくなる：実行ファイル内の文字列照合で自動検知する方法

Claude Code の組み込み Explore サブエージェントを ~/.claude/agents/Explore.md で上書きして model: haiku などに固定すると、モデルだけでなくシステムプロンプト・ツール制限・ description まで丸ごと自作ファイル側へ置き換わります。その結果、Claude Code 本体がアップデートされても組み込み側の仕様変更が見えなくなります。 組み込みサブエージェントの上書きによる仕様ずれ とは、同名の定義ファイルを配置してモデルやツールを変更した結果、本体の内蔵一覧（セッションログ上の builtInTypes ）から対象エージェントが外れて自作定義（ isBuiltIn: false ）へ固定され、本体更新に伴うプロンプトや挙動の改善への追従も観測もできなくなる状態を指します。

サブエージェントのモデル選定に関する比較記事 では Explore.md によるモデル固定と解決仕様を扱いましたが、本記事ではその運用を続けた先に発生する「本家の更新を取り逃す問題」を解決します。構築するのは、外部パッケージ不要の標準 Python 3 スクリプト check.py と ~/.claude/settings.json の SessionStart フックを組み合わせた自動検知の仕組みです。Claude Code のバージョンが変わったときだけ実行ファイル内の固定プロンプト文字列・ description ・公式 CHANGELOG.md を照合し、ずれがあれば警告を出します。構成するファイルは ~/.claude/agents/Explore.md 、 ~/.claude/explore-override/check.py （143 行）、自動生成される ~/.claude/explore-override/last-version 、 ~/.claude/settings.json の 4 つで完結します1。なお、検証環境（2026-11-06 導入〜2026-11-18 確認）では v2.1.318 から v2.1.327 までの実運用アップデートにおける警告発火は 0 件でしたが、修正前のテスト（本文 1 行削除と description 改変）での初回検知、修正後の 1 行削除テストでの継続警告（再通知）、および last-version を 2.1.190 に書き換えた擬似版更新テストで動作を確認しています1。

Explore を上書きすると何が起き、なぜ自動検知が必要なのか

組み込み Explore を同名のカスタム定義で上書きすることの影響と、実行ファイル内部の構造を踏まえた文字列照合の設計方針を整理します。

上書き前後で起きる仕様変更の不可視化（一次ログ実測）

Claude Code の公式仕様では、ユーザー設定やプロジェクト設定に Explore と同名のサブエージェントを配置すると組み込み Explore が上書きされ、独自の model とプロンプトが使われます2。組み込み Explore は v2.1.198 以降、従来の Haiku 固定からメイン会話のモデル継承（Claude API 上では Opus 上限）へ変更されました23。そのため、 コスト最適化の実践記事 でも触れたように、コスト削減の目的で Explore.md を配置する運用が生まれますが、定義ファイルで丸ごと置き換える手法では「Anthropic が調整したプロンプトの喪失」「元のエージェント挙動の推測」「将来の改善の取り逃し」という 3 つの弊害が指摘されています4。

手元の検証環境におけるセッションログ（2026-10-12〜2026-11-18 観測）を比較すると、上書き前後でログ構造に明確な変化が現れます1。

  • 上書き前（2026-10-12〜2026-10-31）: 調査対象の組み込み Explore 実行ログ直近 5 本（応答数 10 / 32 / 9 / 22 / 11 件）は、すべて claude-opus-5-5 で応答していました1。また、2026-11-06 の上書き前セッション冒頭ログ（ agent_listing_delta ）では builtInTypes 配列に "Explore" が含まれ、説明文には簡略版 whenToUseLean （ Read-only search agent for broad fan-out searches... ）が出力されていました1。当時の組み込み Explore （ v2.1.316 ）が api-request-shape で送信していたシステムプロンプト展開長は 3,212 文字でした1。
  • 上書き後（2026-11-06・2026-11-07・2026-11-16）: Explore.md 作成後の 2026-11-07 と 2026-11-16 のセッション冒頭ログでは builtInTypes 配列から "Explore" が外れ、 addedLines 側の Explore 説明文が自作 Explore.md に設定した通常版 whenToUse （ Fast read-only search agent for locating code... (Tools: Bash, Read, Skill, ToolSearch) ）へ置換されました1。さらに 2026-11-06 の上書き作成後に起動したサブエージェント 2 本のメタデータ（ .meta.json ）はいずれも "isBuiltIn": false となり、リクエスト送信時のシステムプロンプト（ api-request-shape ）も v2.1.316 から写した自作本文（1,977 文字）と共通末尾を合わせた計 3,212 文字に固定されました1。

上書き前と同じ文面・同じ文字数で固定されるため、Claude Code 本体が更新されても、セッションログやサブエージェントの出力からは組み込み側の変更を観測できなくなります。なお、 builtInTypes や isBuiltIn 、 agent_listing_delta 、 api-request-shape はセッションログ上の内部構造であり、本体がどの条件で除外や切り替えを行うかの内部機序全体は公開仕様になく断定できません。また、 Explore.md 上書きはモデル変更と同時にプロンプト・ツール制限・ description を置き換えるため、モデル単独の効果とは切り分けていません。

実行ファイル内の構造と 2 系統の description

自動照合の設計にあたって、2026-11-06 時点の v2.1.318 ネイティブ実行ファイル（ 319,598,464 bytes ）を Python の mmap で読み取ったところ、組み込み Explore の定義が文字列としてそのまま埋め込まれていました1。

  • プロンプトテンプレート: return`You are a file search specialist...report your findings clearly.` という JS テンプレートリテラルとして埋め込まれており、内部にはツール名などを埋め込む `${s}` 、 `${h}` 、 `${ze}` 、 `${n}` 、 `${e?...}` のような変数補間が含まれていました1。
  • 2 系統の description: Explore の定義オブジェクト周辺には、 whenToUse （通常版、変数 vfo ）と whenToUseLean （簡略版、変数 Cfo ）の 2 種類が存在しました1。
    • whenToUse: Fast read-only search agent for locating code. ... When calling, specify search breadth: ...
    • whenToUseLean: Read-only search agent for broad fan-out searches — ... Specify search breadth: ...

サードパーティによる抽出スナップショットでも whenToUse と whenToUseLean の 2 系統が記録されています5。また、ネイティブバイナリから strings と awk で Explore.md を手動再生成する公開 Gist スクリプト（ extract-explore-prompt.sh ）も存在しますが、そちらは whenToUseLean 側を採用して `${tool}` 補間ギャップを手動解消する再生成スクリプトであり、版更新時の自動ずれ検知や CHANGELOG.md 照合は持ちません6。

Claude Code 本体がどの条件で whenToUse と whenToUseLean を使い分けるかは公開ドキュメントに記載がない非公開仕様のため、内部仕様は断定しません。また、 v2.1.318 の実行ファイル自体は自動更新の整理により削除されており、2026-11-18 時点でディスク上に残っているのは v2.1.322 〜 v2.1.327 のうち 5 版です1。ただし、 v2.1.326 バイナリでは whenToUse と固定プロンプトの一致を、 v2.1.327 バイナリ（ 354,515,104 bytes ）でもテンプレートと 2 系統の埋め込み、および固定断片・ description の一致を確認しています1。

全体構成図と文字列照合の設計方針

以上の構造を踏まえ、 check.py はハッシュ値ではなく、次の 3 本立てでずれを検査する設計にしました1。

  1. テンプレート固定行の出現順一致: バイナリ内のテンプレートから `${...}` を除いた固定行を抜き出し、 Explore.md 本文に出現順で含まれるか（ body.find ）を照合する
  2. whenToUse 側 description の完全一致: D_START = b"Fast read-only search agent for locating code." から抽出した文字列と、 Explore.md フロントマターの description を文字列比較する（ whenToUseLean 側は照合対象外）
  3. 公式 CHANGELOG.md の正規表現検索: 前回版より新しく現在版以下の見出し配下から \bExplore\b(?!r) （ Explorer を除外）に一致する行を抽出する

全体フローは次のとおりです。

flowchart TD
    A["SessionStart フック発火"] --> B{"last-version == 現在版?"}
    B -- "一致 (--force なし)" --> Z["無出力で exit 0"]
    B -- "不一致または初回" --> C["バイナリを mmap で走査"]
    C --> D["1. 固定プロンプト行の順序包含"]
    C --> E["2. whenToUse 側 description 一致"]
    D --> F["drift = bool(warn) を確定"]
    E --> F
    F --> G{"last-version あり?"}
    G -- "あり" --> H["3. 公式 CHANGELOG.md 検索 (timeout=5)"]
    G -- "なし (初回)" --> I{"warn あり?"}
    H --> I
    I -- "なし" --> J["last-version を更新して exit 0"]
    I -- "あり" --> K{"drift が True?"}
    K -- "True (定義ずれ・目印消失)" --> L["last-version を更新せず警告を stdout 出力 (exit 0)"]
    K -- "False (CHANGELOG のみ/通信失敗)" --> M["last-version を更新し通知を stdout 出力 (exit 0)"]

この設計では 3 つの判断を入れています。

  • 固定行の順序一致を採用した理由: バイナリ内のテンプレートは `${...}` 補間を含み、ビルド時の縮小（minify）で内部変数名だけが変わっても指示内容の本質は同じ場合があります。ネストした `${...}` を飛ばして固定テキスト断片だけを抜き出し順序包含を見ることで、変数名変化によるノイズを避けつつ文面の欠落や順序変更を拾えます（なお、ハッシュ値比較を実装した場合の偽陽性率との比較実測は行っていません）。
  • 無出力成功と警告時のみ出力、かつ exit 0 を返す理由: SessionStart フックは、終了コード 0 のプレーンテキスト標準出力を Claude が参照できるコンテキスト（ system reminder 等、10,000 文字上限）へ注入する一方、セッションをブロックできない仕様です7。終了コード 2 を返してもユーザー画面にエラー通知が出るだけで Claude 側には渡らないため7、正常経路では常に exit 0 を返します。また、問題がないセッションで毎回「確認済み」と出すと慣れで見落としやすいため、異常時だけ出力して意識に引っかかるようにしています。
  • 目印消失時のフェイルセーフ: 実行ファイル内部の文字列や構文は公開 API ではないため、目印（ P_START / P_END / D_START ）が見つからない場合も「構造が変わった可能性」として警告を出します1。

前提環境とファイル構成

check.py は os.path.realpath(shutil.which("claude")) で実行ファイルの実体パスを解決し、末尾のファイル名をバージョン番号（例: 2.1.327 ）として取得した上で、そのネイティブバイナリを mmap で読み取ります1。したがって、macOS の ~/.local/share/claude/versions/<version> のように、実体ファイル名がバージョン文字列になる ネイティブインストーラ版 Claude Code を前提とします（npm インストール等で実体ファイル名が cli.js や claude のままになる構成ではバージョン比較が動作しません）。

外部パッケージのインストールは不要で、Python 3 の標準ライブラリ（ json, mmap, os, pathlib, re, shutil, sys, urllib.request ）のみで動作します。検証環境（macOS）ではシステム標準の /usr/bin/python3 （ Python 3.9.6 ）で --force 実行が exit=0 で完了することを確認しています1。

作成・配置するファイル構成は次の 4 点です（ last-version は初回正常実行時に自動作成されます）。なお、ユーザー全体の ~/.claude/agents/Explore.md よりプロジェクト固有の .claude/agents/Explore.md が優先されるスコープ規則がありますが2、本手順ではユーザー全体を対象に配置します（プロジェクト単位で監視したい場合は、 check.py 内の AGENT パスとフック設定先をプロジェクト配下へ読み替えてください）。

~/.claude/
├── agents/
│   └── Explore.md                 # 組み込みベースの Explore 上書き定義
├── explore-override/
│   ├── check.py                   # 版更新時のみ走る文字列照合スクリプト（143 行）
│   └── last-version               # 最終検査済みバージョンの記録（自動生成）
└── settings.json                  # SessionStart フックの登録先

ステップ1: 組み込みベースの上書き定義（Explore.md）を用意する

目的: 組み込み Explore の読み取り専用プロンプトとツール制限、 whenToUse 側の description を維持したまま、使用モデルを model: haiku へ切り替えるため ~/.claude/agents/Explore.md を作成します。

検証環境で運用している Explore.md のフロントマター（1〜9 行目）と、本文中の読み取り専用制約部分（12〜20 行目）は次のとおりです。

引用元: 検証環境の Explore.md（フロントマター部分）

---
name: Explore
# 組み込み Explore の上書き（2026-11-06）。本文は v2.1.316 の Explore トランスクリプト（api-request-shape）から、
# description は v2.1.318 の実行ファイルから逐語で写した。組み込みの変更は ~/.claude/explore-override/check.py が検知する。
description: "Fast read-only search agent for locating code. Use it to find files by pattern (eg. \"src/components/**/*.tsx\"), grep for symbols or keywords (eg. \"API endpoints\"), or answer \"where is X defined / which files reference Y.\" Do NOT use it for code review, design-doc auditing, cross-file consistency checks, or open-ended analysis — it reads excerpts rather than whole files and will miss content past its read window. When calling, specify search breadth: \"quick\" for a single targeted lookup, \"medium\" for moderate exploration, or \"very thorough\" to search across multiple locations and naming conventions."

model: haiku

実際のファイルはフロントマター（1〜9 行目）を含めて計 42 行で構成されており、本文部分（10〜42 行目）は冒頭の You are a file search specialist for Claude Code... から末尾の Complete the user's search request efficiently and report your findings clearly. まで計 33 行・1,977 文字で、 v2.1.316 の組み込み Explore セッションログ（ api-request-shape ）から写したものです1。後述の意図的破壊テストでは、上記の 15 行目にあたる - Deleting files (no rm or deletion) を削除して検知を確認します。

読者が手元の環境から展開後のプロンプト本文やバイナリ内の whenToUse を取り出して Explore.md を作成する場合、サブエージェントログは公式仕様どおり 2 階層下の ~/.claude/projects/*/*/subagents/agent-*.jsonl に保存されます2。上書き後の isBuiltIn: false ログや古い版のログを拾わないよう、更新日時が最新の isBuiltIn: true ログを優先して探し、ログが手元にない場合は実行バイナリのテンプレート本体と description を取り出す参考例は次のとおりです（手元の環境に合わせて調整して実行してください）。

# 手元の最新の組み込み Explore ログ（isBuiltIn: true）または実行バイナリから文面を確認する参考例
python3 - <<'EOF'
import json, mmap, pathlib, shutil, os

# 1) 更新日時が最新の組み込み Explore ログから展開済みプロンプト（api-request-shape）を探す
found_prompt = False
meta_files = sorted(
    pathlib.Path.home().glob(".claude/projects/*/*/subagents/agent-*.meta.json"),
    key=lambda p: p.stat().st_mtime,
    reverse=True,
)
for meta_path in meta_files:
    meta = json.loads(meta_path.read_text())
    if meta.get("agentType") == "Explore" and meta.get("isBuiltIn") is True:
        jsonl_path = meta_path.with_name(meta_path.name.replace(".meta.json", ".jsonl"))
        if not jsonl_path.exists():
            continue
        for line in jsonl_path.open():
            rec = json.loads(line)
            if rec.get("type") == "api-request-shape":
                text = rec["shape"]["system"][1]["text"]
                end = text.find("report your findings clearly.")
                if end != -1:
                    print("--- PROMPT FROM LOG ---", jsonl_path)
                    print(text[: end + len("report your findings clearly.")])
                    found_prompt = True
                    break
        if found_prompt:
            break

# 2) 実行バイナリから whenToUse の description と（ログ未取得時用に）テンプレート本体を取り出す
exe = pathlib.Path(os.path.realpath(shutil.which("claude")))
with open(exe, "rb") as f, mmap.mmap(f.fileno(), 0, access=mmap.ACCESS_READ) as m:
    if not found_prompt:
        p_start = b"return`You are a file search specialist"
        p_end = b"report your findings clearly.`"
        i = m.find(p_start)
        j = m.find(p_end, i) if i != -1 else -1
        if j != -1:
            print("--- PROMPT TEMPLATE FROM BINARY ---")
            print(m[i + len(b"return`") : j + len(p_end) - 1].decode())

    marker = b"Fast read-only search agent for locating code."
    k = m.find(marker)
    if k != -1:
        q = m[k - 1 : k]
        raw = m[k : m.find(q, k)].decode()
        desc = json.loads('"' + raw.replace('"', '\\"') + '"') if q == b"'" else raw
        print("--- DESCRIPTION FROM BINARY ---")
        print(json.dumps(desc, ensure_ascii=False))
EOF

未上書きのサブエージェントログが手元にない場合は、上のスクリプトが出力した --- PROMPT TEMPLATE FROM BINARY --- の本文から `${...}` 変数補間部分を自分の tools 設定に合わせた記述（ Guidelines: 直下の検索ツール指示 2 行、ファイル読み取り用の Read 、読み取り専用シェル用の Bash と許可・禁止コマンド群）に置き換えて本文を組み立てます。後述の check.py （ literal_parts() ）は `${...}` で囲まれた部分をすべて除外し固定行だけを順序照合するため、補間部分の文言を手元環境に合わせて埋めても照合は通過します。なお、全文スナップショットや `${tool}` 補間の手動解消スクリプトの実装例は公開資料も参考にできます56。

重要箇所の解説:

  • description: を JSON 文字列形式で 1 行に書く理由: 後述する check.py の agent_parts() は、フロントマターから正規表現 ^description:\s*(.*)$ で 1 行を取り出し、 json.loads() でパースしています1。そのため、ダブルクォートで囲み内部の " を \" でエスケープした 1 行の JSON 文字列として記述する必要があります（複数行 YAML にするとパースエラーになります）。
  • 初版作成からの修正経緯: 初版を作成した時点では、本文先頭に HTML コメントを置き、 description も末尾の "When calling, specify search breadth: ..." がない短縮文を手書きしていました1。その直後に、コメントをフロントマター内の # ... へ移し、 description を v2.1.318 実行ファイルから抽出した完全文字列へ差し替えています1。本文の由来は v2.1.316 トランスクリプト、 description の由来は v2.1.318 バイナリとバージョンが異なりますが、 v2.1.318 ・ v2.1.326 ・ v2.1.327 のいずれに対しても固定部分の一致を確認済みです1。
  • tools と omitClaudeMd: true の位置づけ: tools: Bash, Read, Skill, ToolSearch は、本文内の find / grep を Bash で使う指示と整合する読み取り中心の構成であり、 Edit や Write を外しています（ Grep や Glob を使う構成にする場合は本文の該当行も合わせて調整します）。また、公式ドキュメントには、組み込み Explore と Plan だけが CLAUDE.md と親セッションの git status スナップショットを省略する旨が書かれています2。一方、 omitClaudeMd: true は v2.1.271 以降で言及されているカスタム定義向けの CLAUDE.md 省略オプションであり8、サードパーティのバイナリ定義スナップショットにも同フィールドが含まれています5。ただし、検証環境の自作 Explore.md （ isBuiltIn: false ）において CLAUDE.md や git status が実際にどこまで省略されるか自体は実測していないため、ここでは設定の記載に留めます。

ステップ2: 版更新時だけ走る照合スクリプト（check.py）を実装する

目的: セッション起動のたびに呼び出しても同版なら即終了し、Claude Code のバージョンが変わったときだけ実行ファイルと公式 CHANGELOG.md を照合する ~/.claude/explore-override/check.py を配置します。

まず mkdir -p ~/.claude/explore-override でディレクトリを作成し、以下の 143 行のスクリプトを ~/.claude/explore-override/check.py として保存したあと chmod +x ~/.claude/explore-override/check.py で実行権限を付けておきます（実行時は /usr/bin/python3 の引数として渡して呼び出すためシバンに依存しません）。

引用元: 検証環境の check.py

#!/usr/bin/env python3
"""組み込み Explore と ~/.claude/agents/Explore.md（上書き定義）のずれを検知する。

Claude Code の版が変わったときだけ走る（SessionStart hook 用。同じ版なら何も出さない）。
- 実行ファイル内の Explore プロンプト（テンプレート文字列）の固定部分が、上書き定義の本文に順に含まれるか
- 実行ファイル内の Explore description が、上書き定義の description と一致するか
- 公式 CHANGELOG の、前回確認した版より新しい項目に「Explore」を含む行があるか
ずれがあれば標準出力に警告を出す（hook の出力はセッションの文脈に入る）。常に exit 0。
実行ファイルの中身は公開仕様ではないので、目印が見つからないときも「変わった」として警告する。

使い方: check.py [--force]   （--force は版が同じでも検査する）
"""
import json, mmap, os, pathlib, re, shutil, sys, urllib.request

HOME = pathlib.Path(os.environ.get("HOME"))
AGENT = HOME / ".claude/agents/Explore.md"
STATE = HOME / ".claude/explore-override/last-version"
CHANGELOG = "https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md"
P_START = b"return`You are a file search specialist"
P_END = b"report your findings clearly.`"
D_START = b"Fast read-only search agent for locating code."


def binary():
    exe = shutil.which("claude")
    return pathlib.Path(os.path.realpath(exe)) if exe else None


def ver_tuple(v):
    return tuple(int(x) for x in re.findall(r"\d+", v))


def extract(path):
    with open(path, "rb") as f, mmap.mmap(f.fileno(), 0, access=mmap.ACCESS_READ) as m:
        i = m.find(P_START)
        j = m.find(P_END, i) if i != -1 else -1
        prompt = m[i + len(b"return`"):j + len(P_END) - 1].decode() if j != -1 else None
        k = m.find(D_START)
        desc = None
        if k != -1:
            q = m[k - 1:k]
            raw = m[k:m.find(q, k)].decode()
            desc = json.loads('"' + raw.replace('"', '\\"') + '"') if q == b"'" else raw
    return prompt, desc


def literal_parts(template):
    """テンプレート文字列から ${...} を除いた固定部分（ネストした ${} とバッククォートも飛ばす）。"""
    parts, buf, i, n = [], [], 0, len(template)
    while i < n:
        if template.startswith("${", i):
            parts.append("".join(buf)); buf = []
            depth, i = 1, i + 2
            while i < n and depth:
                c = template[i]
                depth += c == "{"
                depth -= c == "}"
                i += 1
        else:
            buf.append(template[i]); i += 1
    parts.append("".join(buf))
    return [p.strip() for p in parts if p.strip()]


def agent_parts():
    text = AGENT.read_text()
    _, fm, body = text.split("---\n", 2)
    m = re.search(r"^description:\s*(.*)$", fm, re.M)
    desc = json.loads(m.group(1)) if m else None
    return desc, body


def check_prompt(template, body):
    pos, missing = 0, []
    for part in literal_parts(template):
        for line in part.splitlines():
            line = line.strip()
            if not line:
                continue
            k = body.find(line, pos)
            if k == -1:
                missing.append(line)
            else:
                pos = k + len(line)
    return missing


def changelog_hits(since, upto):
    try:
        text = urllib.request.urlopen(CHANGELOG, timeout=5).read().decode()
    except Exception as e:  # ネットワーク不達でも本体の検査は済ませる
        return None, str(e)
    hits, cur = [], None
    for line in text.splitlines():
        h = re.match(r"^## (\d+\.\d+\.\d+)", line)
        if h:
            cur = h.group(1)
            continue
        if cur and ver_tuple(since) < ver_tuple(cur) <= ver_tuple(upto) and re.search(r"\bExplore\b(?!r)", line):
            hits.append(f"{cur}: {line.strip()}")
    return hits, None


def main():
    force = "--force" in sys.argv
    exe = binary()
    if not exe or not AGENT.exists():
        return
    version = exe.name
    last = STATE.read_text().strip() if STATE.exists() else None
    if last == version and not force:
        return
    warn = []
    prompt, desc = extract(exe)
    a_desc, body = agent_parts()
    if prompt is None:
        warn.append("実行ファイルに Explore プロンプトの目印が見つからない（構造が変わった可能性）")
    else:
        missing = check_prompt(prompt, body)
        if missing:
            warn.append("組み込みプロンプトにあって上書き定義に無い行:\n" + "\n".join(f"    {l}" for l in missing))
    if desc is None:
        warn.append("実行ファイルに Explore description の目印が見つからない")
    elif desc != a_desc:
        warn.append(f"description が組み込みと違う。組み込み:\n    {desc}")
    drift = bool(warn)  # 定義のずれは直るまで毎セッション出す。CHANGELOG の該当は版ごとに1回だけ
    if last:
        hits, err = changelog_hits(last, version)
        if err:
            warn.append(f"CHANGELOG を取得できず未確認（{err}）")
        elif hits:
            warn.append("CHANGELOG に Explore の変更:\n" + "\n".join(f"    {h}" for h in hits))
    if warn:
        print(f"[explore-override] Claude Code {last or '?'} → {version}: 組み込み Explore と {AGENT} のずれを確認してください")
        for w in warn:
            print("- " + w)
    if not drift:
        STATE.parent.mkdir(parents=True, exist_ok=True)
        STATE.write_text(version + "\n")


if __name__ == "__main__":
    main()

重要箇所の解説:

  • binary() （L24–L26）: shutil.which("claude") を os.path.realpath() で辿り、 exe.name （例: 2.1.327 ）を版番号として取得します。実体ファイル名が数値バージョンでない配置では ver_tuple() が空タプルになり版更新の比較が働きません。
  • extract() （L33–L44）: バイナリを mmap.ACCESS_READ で開き、 P_START 〜 P_END の範囲と、 D_START 直前の引用符（ ' か " ）に対応した終端までの文字列を取り出します。シングルクォートで囲まれていた場合は内部のダブルクォートをエスケープした上で json.loads により文字列をデコードしています（ q == b'"' 側の分岐は文字列内にエスケープされた \" を含まない単純な構成を想定しており、現行バイナリで D_START 文字列がシングルクォート囲みかつ内部に ' を含まない前提で動作しています）。
  • literal_parts() （L47–L62）: 波括弧のネスト深さ depth を数えながら `${...}` をスキップし、変数の入らない固定テキスト断片だけを抜き出します。
  • check_prompt() （L73–L85）: 抽出した各非空行が Explore.md 本文に出現順で含まれているかを body.find(line, pos) で検査し、1 行でも欠落または順序逆転があれば missing に積みます。
  • changelog_hits() （L88–L101）: urllib.request.urlopen(CHANGELOG, timeout=5) で公式 CHANGELOG.md を取得し、 last < cur <= version の見出し配下から \bExplore\b(?!r) （ Explorer を除く）に一致する行を拾います。通信に失敗した場合は例外を握りつぶさずエラー文字列を返し、本体バイナリの照合結果を優先して出力します（ただし後述の drift が False のときはオフラインの回でも last-version が更新されるため、通信失敗だった回の CHANGELOG 照合は次回へ持ち越されません）。

実装時に踏んだバグ：警告が出ても last-version を更新してしまう問題

check.py の初版では、 warn リストにずれが入っていても、 main() の末尾で無条件に状態ファイルを更新していました1。

引用元: 検証環境の初期版 check.py

    STATE.parent.mkdir(parents=True, exist_ok=True)
    STATE.write_text(version + "\n")

この作りだと、1 回目の起動で警告が出た瞬間に last-version が現在版へ書き換わるため、2 回目以降の起動では last == version と判定されて無出力で素通りしてしまいます。実際に後述の破壊テストの 2 回目でこの欠陥が露呈しました1。

そこで、 changelog_hits() を呼ぶ直前に drift = bool(warn) として「バイナリ内の定義側のずれ・目印消失」の有無だけを記録し、 if not drift: のときだけ last-version を更新するよう改めました1。

引用元: 検証環境の修正版 check.py

    drift = bool(warn)  # 定義のずれは直るまで毎セッション出す。CHANGELOG の該当は版ごとに1回だけ
    if last:
        hits, err = changelog_hits(last, version)
        if err:
            warn.append(f"CHANGELOG を取得できず未確認（{err}）")
        elif hits:
            warn.append("CHANGELOG に Explore の変更:\n" + "\n".join(f"    {h}" for h in hits))
    if warn:
        print(f"[explore-override] Claude Code {last or '?'} → {version}: 組み込み Explore と {AGENT} のずれを確認してください")
        for w in warn:
            print("- " + w)
    if not drift:
        STATE.parent.mkdir(parents=True, exist_ok=True)
        STATE.write_text(version + "\n")

この分離により、定義側にずれがないとき（ drift == False ）は CHANGELOG.md の変更通知や取得失敗警告を版更新の 1 回だけ出しつつ last-version が進み、逆に定義側にずれがある間（ drift == True ）は last-version が進まないため、 Explore.md または check.py を修正するまで毎セッション警告と CHANGELOG 通知が出続けます。

ステップ3: SessionStart フックに登録する（mise shim 回避）

目的: ~/.claude/settings.json の hooks.SessionStart に check.py を登録し、セッション開始・再開時に自動実行されるようにします。

ここで検証時に踏んだ重要なハマりどころが mise などのバージョン管理 shim です1。テストのために HOME を一時ディレクトリへ差し替えて python3 （ mise の shim）を実行したところ、元のホームディレクトリ配下の設定ファイル（ ~/.config/mise/config.toml ）が新しい HOME から未信頼扱いとなり、 mise ERROR ... config.toml are not trusted が出て exit=1 で失敗しました1。フックが動く環境の PATH や shim 設定に左右されないよう、外部ライブラリを使わない check.py にはシステム標準の /usr/bin/python3 （macOS 環境では Python 3.9.6 、 --force 実行 exit=0 を確認済み）をフルパスで指定する方針にしました1。

~/.claude/settings.json の hooks.SessionStart に追加する定義は次のとおりです（既存の SessionStart フックがある場合は上書きせず配列の末尾に追記します）。

{
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "/usr/bin/python3 ~/.claude/explore-override/check.py"
          }
        ]
      }
    ]
  }
}

既存の ~/.claude/settings.json を壊さずに hooks.SessionStart 配列の末尾へ 1 項目追記したい場合は、次のワンライナーで安全に更新できます（ ~/.claude/settings.json がまだ存在しない場合は、事前に echo '{}' > ~/.claude/settings.json で空の JSON ファイルを作成してから実行してください）。

/usr/bin/python3 -c "import json,pathlib;p=pathlib.Path.home()/'.claude/settings.json';d=json.loads(p.read_text());d.setdefault('hooks',{}).setdefault('SessionStart',[]).append({'hooks':[{'type':'command','command':'/usr/bin/python3 ~/.claude/explore-override/check.py'}]});p.write_text(json.dumps(d,ensure_ascii=False,indent=2)+'\n')"

登録後、システム標準の /usr/bin/python3 で --force 実行がエラーなく終了するかを確認します。

/usr/bin/python3 --version && /usr/bin/python3 ~/.claude/explore-override/check.py --force; echo "exit=$?"

検証環境での実行結果（一次記録に基づく出力）は次のとおりです1。

Python 3.9.6
exit=0

重要箇所の解説:

  • SessionStart の発火範囲: SessionStart フックは通常の新規起動だけでなく、 --continue や --resume （ source が "resume" ）、 --fork-session （ "fork" ）、 /clear の実行時にも発火します7。インタラクティブ起動ではバックグラウンドで走りつつ Claude の初回応答前に完了を待ちます7。
  • 設定の配置スコープ: フック設定もサブエージェント定義と同様にユーザー全体の ~/.claude/settings.json とプロジェクトごとの .claude/settings.json 等でスコープが分かれており9、今回はユーザー全体の Explore.md に合わせて ~/.claude/settings.json に配置しています。

次に、本番の ~/.claude/explore-override/last-version を汚さないよう一時的な HOME ディレクトリを作り、 Explore.md から - Deleting files (no rm or deletion) の 1 行を削除して実行し、壊れている間は毎回警告が出て、復元後に無出力へ戻るかを確かめます。以下は /usr/bin/python3 を使って独立環境で試せる再現コマンドです（検証環境では mise shim を回避した実体パスで実行しました1）。

検証環境（ v2.1.318 ）での修正前後の挙動差は次のとおりでした1。

  • 修正前（初版）: 本文 1 行削除と description 改変を同時に行ってテストしたところ、1 回目は両方の警告が出たものの、2 回目は last-version 更新済みのため無出力で素通りしました1。
  • 修正後（ if not drift: 追加後）: 本文 1 行削除の状態で 2 回連続実行したところ、1 回目・2 回目とも通知ヘッダに続けて欠落行の警告が出力され続け、元の Explore.md を復元した直後の 1 回目で last-version に 2.1.318 が記録されて無出力・ exit=0 に戻りました1。
- 組み込みプロンプトにあって上書き定義に無い行:
    - Deleting files (no rm or deletion)

exit=0 state=2.1.318
--- 修正後 2 回目
exit=0 state=2.1.318

（注: 検証ログの実測出力から抜粋しているため、コマンド側のラベル行 --- ずれあり ... や通知ヘッダ行、および 2 回目の重複する警告行は省略しています。）

なお、修正前のテストでは「本文 1 行削除」と「 description 改変」を同時に行ったのに対し、修正後のテストでは「本文 1 行削除」のみを実施しているため、 description 単体を改変した際の継続警告挙動は同テストでは単体切り分けしていません（コード上は同じ warn リストから drift = bool(warn) を判定しています）。

3. 現行バイナリでの読み取り専用検算（2026-11-18 時点）

last-version の書き換えや外部通信を行わずに、現存する実行ファイルと Explore.md の一致だけを確かめたい場合は、 check.py をモジュールとして読み込んで検査関数を直接呼び出せます。

/usr/bin/python3 - <<'EOF'

運用上の制約・実証範囲の境界と代替手段の比較

導入後の運用実態と、この仕組みがカバーできる範囲・代替手段との使い分けを整理します。

実運用の現在地と検証できていない領域

検証環境では 2026-11-08 以降も Explore.md を変更せず維持しており（2026-11-17 のプロンプト監査でも読み取り専用の逐語コピーとして残す判断）、2026-11-18 11:08 時点では last-version が 2.1.327 まで自動追従しています1。

ただし、導入（2026-11-06 v2.1.318 ）から v2.1.327 （2026-11-18 時点）までの全セッションログ検索および筆者の確認範囲において、 実版更新を契機に [explore-override] 警告が発火した実例はまだ 0 件 です1。本仕組みの検知動作はあくまで先述の意図的破壊テストと擬似版更新テストで確認したものであり、実版更新での発火頻度や検知率は未計測です。

また、運用上は次の 4 点の境界・制約があります。

  1. ネイティブ配置とバイナリ内部構文への依存: exe.name による版番号取得と mmap はバージョン文字列の実行ファイル名で配置されるネイティブインストーラ版を前提としており、npm 版など配置が異なる環境では更新検知が動作しません。また P_START / P_END / D_START は非公開の実装文字列に依存するため、将来のどの版で構文が変わって壊れるかは予測できません（消失時はフェイルセーフで警告が出ます）。
  2. whenToUseLean と ${...} 変数の対象外: check.py は whenToUse 側のみを照合しており、 whenToUseLean 側や `${...}` 変数展開の中身だけが変化した場合の差は検知しません。また v2.1.318 バイナリは自動更新で整理されているため、現存する v2.1.322 〜 v2.1.327 分を除き、全期間を通じて whenToUseLean や `${...}` が変化したかは遡って切り分けられません1。
  3. CHANGELOG.md のオフライン耐性と網羅限界: ネットワーク不達時は timeout=5 （5 秒）でタイムアウトして未確認の警告を出しつつバイナリ照合を優先します。ただし drift == False （定義側が一致）のときはオフラインの回でも last-version が更新されるため、その回に取得できなかった CHANGELOG の範囲は次回再照合されません。また CHANGELOG.md に Explore の語を含まない微調整はバイナリ照合側で拾う前提です。
  4. 未計測の領域: カスタム Explore.md （ isBuiltIn: false ）で omitClaudeMd: true を指定した場合の CLAUDE.md や git status の実挙動、および whenToUseLean との切り替えによる呼び出し精度差は本検証の計測範囲外であるため、公式仕様上の挙動の参照に留めています。

代替手段との比較：モデル固定・制御の 4 パターン

組み込みプロンプトの変更追従性を保ったままモデルだけを一律で下げたい場合は CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1 の併用または呼び出し時の model 指定を選び、コード編集を行う他のサブエージェントのモデルを変えずに Explore だけをツール制限ごと安全に固定したい場合は Explore.md 上書きと check.py 監視の併用を選びます。

方式対象範囲組み込みプロンプトの追従他サブエージェントへの影響向いている用途
Explore.md 上書き ＋ check.py 監視Explore のみ（ ~/.claude/agents/ または .claude/agents/ ）自動追従しない（版更新時に自動で差分警告）なしExplore だけモデルやツールを固定し、仕様変化を逃したくない場合
CLAUDE_CODE_SUBAGENT_MODEL ＋ CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1全サブエージェント・teammate・workflow agent（ v2.1.257 以降）組み込みプロンプトのまま追従（ Explore に適用）あり （ general-purpose 等も含め全指定モデルへ強制）コード編集を含む全サブエージェントを一律に同一モデルへ固定したい場合
呼び出し時の model 指定その 1 回の委任のみ組み込みプロンプトのまま追従なし特定タスクだけ一時的に Haiku 等へ逃がしたい場合
CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS=1組み込み Explore / Plan の無効化（ v2.1.198 以降）組み込み自体を使わない（通常の検索ツールや general-purpose を使用）検索が汎用側へ移る組み込み Explore の挙動や CLAUDE.md スキップを丸ごと避けたい場合

ここで注意したいのは、 CLAUDE_CODE_SUBAGENT_MODEL=haiku を単独で設定しても、 v2.1.251 以降は組み込み Explore と Plan のモデルが変わらない点です210。Developers Digest（2026-10-09 更新）による Claude Code v2.1.295 （メインモデル Sonnet 5.5）でのヘッドレス実測でも、 CLAUDE_CODE_SUBAGENT_MODEL=haiku 単独では Explore は Sonnet 5.5 のまま（18,249 トークン / 6.5s）であり、 CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1 併用で Haiku 5.5（18,656 トークン / 5.3s）、 --agents での Explore 上書きで Haiku 5.5（14,088 トークン / 3.8s）になったと報告されています8。同記事では 100K トークン以下の単価（100 万トークンあたり Haiku 5.5 が入力 $0.10・出力 $0.50、Sonnet 5.5 が入力 $2.00・出力 $10.00、Opus 5.5 が入力 $4.00・出力 $20.00）から、Haiku 5.5 は Opus 5.5 比で 40x、Sonnet 5.5 比で 20x 安価であると試算しています8。一方で、Terminal-Bench 4.0 では Haiku 5.5 が 39.2% であるのに対し Sonnet 5.5 は 70.6% を記録しています8。そのため同記事は、コード編集を行うサブエージェントまで一律で Haiku へ固定する CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1 の常時適用には慎重であるべきだと指摘しています8。

よくある質問（FAQ）

Q. ~/.claude/agents/Explore.md で Explore を上書きすると何が置き換わりますか？

A. モデル指定だけでなくシステムプロンプト・ツール構成・ description も自作ファイル側へ置き換わり、セッションログ上では組み込みエージェント一覧（ builtInTypes ）から外れて isBuiltIn: false として扱われます。そのため Claude Code 本体がアップデートされても、自作ファイルを更新しない限り新しい組み込みプロンプトは使われません。

Q. check.py はなぜハッシュ値ではなく固定文字列と description で照合しているのですか？

A. バイナリ内の組み込みプロンプトは JS テンプレートリテラルとして `${...}` の変数補間を含んでおり、変数名や補間構文の変化を避けて実文面の変更だけを検知するためです。 check.py は `${...}` を除いた固定行が Explore.md 本文に出現順で含まれるか、 whenToUse 側の description が一致するか、公式 CHANGELOG.md に Explore を含む更新があるかの 3 点を確認します。

Q. CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1 と Explore.md 上書き＋監視はどう使い分けるべきですか？

A. 組み込みプロンプトの追従を保ったまま全サブエージェントのモデルを一律に固定したいなら CLAUDE_CODE_SUBAGENT_MODEL と CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1 の併用、コード編集を行う general-purpose 等のモデルを変えずに Explore だけモデルやツールを制御しつつ本家の更新ずれも検知したいなら Explore.md 上書きと check.py 監視を選びます。なお CLAUDE_CODE_SUBAGENT_MODEL 単独では組み込み Explore のモデルは変わりません。

Q. Claude Code のアップデートでバイナリ内の目印（P_START 等）が消えた場合はどうなりますか？

A. check.py は「実行ファイルに Explore プロンプト（または description）の目印が見つからない」という警告を標準出力へ出し、 last-version を更新せずに正常経路では exit 0 で終了します。セッション開始をブロックせず、「構造が変わった可能性がある」ことを毎セッション通知するため、安全側に倒して手動確認へ移れます。

まとめ

  • ~/.claude/agents/Explore.md による組み込み Explore の上書きは、モデル解決だけでなくプロンプトと description を丸ごと置き換え、セッションの builtInTypes から外れて isBuiltIn: false に固定されるため、放置すると本家の仕様変更が見えなくなる。
  • 版更新時だけバイナリ内の固定プロンプト行（ literal_parts() ）・ whenToUse 側 description ・公式 CHANGELOG.md の \bExplore\b(?!r) 行を照合し、 drift = bool(warn) と if not drift: で「ずれがある間は毎回警告を出し、解消後にだけ last-version を更新する」設計にすれば、一度きりの素通りを防げる。
  • 外部ライブラリ不要の標準 Python をシステム標準のフルパス（ /usr/bin/python3 ）で SessionStart フックに登録し、正常経路で exit 0 を返すことで、 mise 等の shim による環境依存エラーを避けつつセッション開始を止めずに警告をコンテキストへ注入できる。
  • 導入後から v2.1.327 （2026-11-18 時点）までの実運用では実版更新による警告発火が 0 件であり、実環境での発火頻度は未計測である一方、初回破壊テスト（ Explore.md 1 行削除＋ description 改変）と修正後の 1 行削除テスト・擬似版更新テスト（ 2.1.190 ）で検知と再通知の動作を確認できている。
