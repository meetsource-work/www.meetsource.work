Claudeが料金体系を大幅アップデート！Pro/Teamユーザーに配られた「$100移行クレジット」の正体と正しい確認・活用方法

はじめに：突然届いた「$100分のギフト」

2026年7月20日頃から、多くの Claude Pro ユーザーや Team Standard プランの契約者の元に、Anthropic社から「one-time $100 usage credit（1回限り100ドルの利用クレジット）」が付与されたという通知が届き、開発者の間で大きな話題となっています。

「何もしていないのに、なぜ突然100ドルものクレジットがもらえたのか？」「このクレジットは何に使えるのか？」と疑問に思った方も多いのではないでしょうか。

このクレジットの正体は、同日に実施された Claudeの料金体系および最上位モデル「Claude Fable 5」の提供ポリシー変更に伴う移行措置（クッション） です。本記事では、この仕様変更の真実と、もらった $100 クレジットを無駄にせず適切に活用するための技術的な注意点について解説します。

2026年7月20日の料金・仕様変更の真実

今回の $100 クレジット配布の背景には、最上位モデルである「Claude Fable 5」の利用制限および提供ポリシーの大幅な変更があります。今回のアップデートにより、プランごとに以下のように提供方法が整理されました。

  • Max / Team Premium / Enterprise Premium プラン
    • Fable 5 の利用枠が「週の標準的な使用量制限（weekly usage limits）の最大50%分まで」追加料金なしでプランの定額枠に含まれます。
  • Pro / Team Standard プラン
    • Fable 5 の利用は完全に定額枠外となり、 「Usage credits（利用クレジット）」を用いた従量課金制（pay-as-you-go） に移行しました。

つまり、これまで Pro プラン等で利用できていた Fable 5 が、今後は定額料金とは別枠の従量課金でしか使えなくなったのです。この突然の仕様変更によるユーザーへの負担と混乱を和らげるため、Anthropic社は対象ユーザー（日本時間2026年7月20日 15:59時点でアクティブだった契約者）に対して、1回限り $100 分の移行クレジットを無償で付与しました。

【公式ドキュメントより】Fable 5 の安全対策と自動フォールバック仕様

Fable 5 を実務で利用する上で、AIエンジニアやシステムアーキテクトが絶対に把握しておくべきなのが、 自動フォールバック（fallback）仕様 です。公式ヘルプセンター（support.claude.com）の情報によると、以下のような技術的挙動が定義されています。

Fable 5 は「Covered Model (Mythos-class)」に分類されており、強力な推論能力を持つ反面、サイバーセキュリティ、バイオ/化学、推論抽出などの高リスク領域において自動的な安全チェック（セーフガード）が入ります。このトリガーに触れた場合、安全措置として 自動的に別のモデル（2026年5月にリリースされた Opus 4.8 など）へのフォールバック が発生します。

フォールバックを検知・管理する方法

フォールバックが発生した際、APIはエラー（HTTP 500など）を返すのではなく、HTTP 200の正常レスポンスを返します。そのため、システム側で自動的に検知して制御するには、レスポンスのパースが必要です。

  1. APIレスポンスの確認: レスポンス内の content ブロックをチェックし、type が "fallback" になっているブロックが含まれている場合、フォールバックが発生しています。
  2. refusal の確認: stop_details の category に、原因となったセーフガードカテゴリ（"cyber", "bio", "reasoning_extraction" など）が含まれているか確認します。
  3. 課金挙動: フォールバックが発生した場合、基本的に元の拒否されたリクエストに対する課金は無料化され、二重課金を避けるクレジット処理が適用されるため、コスト面での大きな不利益は生じないよう設計されています。

クレジットの確認手順と使い切った後の注意点

付与された $100 クレジットは、管理画面から簡単に確認できます。ただし、確認や設定の際は 管理画面の混同 に注意してください。

確認手順

今回の移行クレジットや設定は、APIキーを発行する開発者向けの API Console（console.anthropic.com）ではなく、Webサブスクリプション版の claude.ai の Settings > Usage（設定 > 使用量） で管理されます。

  1. claude.ai にログインし、メニューから Settings（設定）を開きます。
  2. Usage（使用量）タブにアクセスすると、現在適用されている移行クレジットの残高を確認できます。

使い切った後の挙動とベストプラクティス

今回配布された $100 クレジットは1回限りの使い切りです。クレジットを使い切った後も Fable 5 などの高度な機能をシームレスに使い続けたい場合は、同画面でクレジットカード情報を登録し、 自動リロード（auto-reload） を有効に設定することで、pay-as-you-go（従量課金）へ移行できます。

ただし、予期せぬ過剰な課金を防ぐために、自動リロードを有効にする際は必ず Adjust limit をクリックして 「Spending Limit（月間の利用限度額）」を設定しておくこと が推奨されます。

なお、今回の措置は、2026年4月に実施された移行クレジット（Proユーザーに$20、Maxユーザーに$100などを付与したキャンペーン）とは異なる、新規の変更点となります。

結論：もらった $100 で Claude Code を検証しよう（認証の落とし穴）

無償で提供された $100 クレジットは、ターミナル上で自律的に動作するコーディング支援ツール 「Claude Code」 の実務検証に最適な予算です。

ただし、Claude Code でこのクレジットを消費しようとする際、エンジニアが陥りがちな 「認証の落とし穴」 が存在します。

環境変数との競合に注意！

CLIツールである Claude Code は、通常 claude auth login コマンドでログインすることで、Webサブスクリプション（OAuth認証）に紐づいたアカウントの Usage credits を消費して動作します。

しかし、もし開発環境のローカル環境変数に ANTHROPIC_API_KEY が設定されている場合、Claude Code の仕様として環境変数が最優先で使用されます。その結果、せっかくの $100 クレジット（Webアカウント側）が消費されず、API Console（console.anthropic.com）の API 残高から課金が引かれてしまう事態が発生します。

解決策

  1. 一時的に環境変数 ANTHROPIC_API_KEY を unset します。 
    unset ANTHROPIC_API_KEY
  2. その状態で claude auth login を実行し、Webサブスクリプションのアカウントで認証を行います。
  3. セッション内で /status コマンドを実行し、現在の認証状態が「Subscription-based OAuth」になっていることを確認します。（claude auth status コマンドでも確認可能です）
  4. /usage（または /cost, /stats）コマンドを実行して、現在のセッションコストやプラン制限を確認しながら開発を進めましょう。

まとめ

今回の仕様変更により、Claude の最上位モデルの利用は従量課金への移行が進みましたが、無償配布された $100 を正しく設定・認証することで、Claude Code を用いた自律型エージェント開発の強力なパワーをノーリスクで体験することができます。ぜひこの機会に、環境変数の設定を見直して、高度なエージェントコーディングを試してみてください。
